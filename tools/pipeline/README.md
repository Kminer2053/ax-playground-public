# 파이프라인 정합성 도구

규정 개정 → 임베딩·그래프·업무온톨로지·흐름도 연쇄 갱신의 기준선을 관리한다.

| 파일 | 역할 |
|---|---|
| `backfill-hashes.mjs` | 조문 srcHash 부여 + 엣지 해시 마이그레이션(레거시 200자 → 전체본문) + 소관·전결 해시 백필. 기본 dry-run, `--apply`로 반영 |
| `diagnose-stale.mjs` | 근거 해시 불일치를 원인별(파싱 변화 / 증감 / 실제 개정)로 분류 진단 |
| `../../src/lib/asset-status.ts` | 문서별 파이프라인 상태 집계(조문·임베딩·그래프·표·업무근거·보드) — 화면·CLI 공용 |
| `npm run assets:backfill` | 전 문서 상태를 집계해 `asset_status`에 기록. `--fix-hash` 해시 보정 · `--analyze` 근거 영향 판정 동반 |
| `/admin` → 사규 → 근거 재검토 | 격리된 근거를 사람이 조치(유지·교체·삭제). 격리는 자동, 해소는 사람 |
| `npm run assets:realign` | 파싱 잡음으로 어긋난 행 앵커를 현재 원문에 맞춤(판정용 `rowText`만 갱신, `quote`는 보존). 기본 dry-run |

해시 규약은 `src/lib/article-hash.ts` **한 곳**에만 둔다. 규약이 갈라지면 개정 감지가 통째로 오탐/미탐이 된다.

상태는 **기록이 아니라 집계**다. 적재 라우트가 결과를 적어두는 방식만 쓰면 CLI·백필·정규화 스크립트로 DB가 바뀔 때 조용히 어긋난다(이 리포는 그런 스크립트가 많다). `computeAssetStatus`는 언제나 현재 DB에서 다시 세고, `asset_status` 컬렉션은 그 결과의 캐시다.

## 이력

- 2026-07-31 P0: 초기 생성기가 조문 **앞 200자**만 해시해 201자 이후 개정이 감지되지 않는 사각지대가 있었다.
  전체 본문 기준으로 격상하고 레거시 해시 225건을 오탐 없이 마이그레이션. 조문 18,481개 전부 해시 부여.
  대조 가능 엣지 435 → 913건. 실제 본문 변경 0건(현행 근거는 원문과 일치).
- 2026-08-03 P4: 문서 상세(사규>현황>[상세 보기]). 조문·임베딩·지식그래프·표·업무영향 5탭 +
  재실행 3종(근거 재판정 / 표 재태깅 / 임베딩·그래프 재구성). 재실행 결과는 수치를 그대로 보여준다 —
  임베딩 서버가 꺼져 있으면 벡터 0개인 채로 "성공"할 수 있어 경고를 함께 싣는다.
  외부 규범은 재구성·재태깅을 막고 이유를 응답한다(격리 대상이라 만들지 않는 것이 정상).
- 2026-08-03 P6: 흐름도 연동. 보드 조회에 `staleRefs`(그 업무의 격리 근거 수)를 붙이고 모달에
  "근거 확인 필요" 배지를 단다 — 보드는 생성 시점 근거로 만들어졌으므로 근거가 어긋나면 흐름도도
  낡았을 수 있다. 내용은 그대로 두고 사실만 알린다(자동 재생성 금지 — LLM 생성물이라 검증 루프가
  다시 필요하다). 보드가 참조하는 근거는 별도 저장본보다 **업무 id 조인**이 항상 최신이라 그렇게 했고,
  생성 시점 앵커(`refsAnchors`)는 "그 뒤 근거가 바뀌었나"를 알 수 있도록 DB에도 함께 저장한다
  (기존에는 파일에만 있었다).
- 2026-08-03 P5: 근거 재검토 화면(`/admin` 사규>근거 재검토). 격리는 자동이지만 해소는 사람의 몫이라
  화면이 없으면 스크립트로만 풀 수 있었다. 업무 단위로 묶고 격리 시점 인용 ↔ 현재 원문을 diff로 보여준다.
  인용은 조문의 일부(200자)인데 조문은 수천 자라, 대응 구간만 발췌해야 "조문 전체가 새로 생겼다"로
  보이지 않는다(실화면에서 확인하고 고쳤다). 조치 3종 모두 실 API로 검증 — 유지(격리 해제·앵커 갱신),
  교체(없는 조문 거부 → 실재 조문 이동), 삭제.
- 2026-08-03 P2: 개정 → 근거 격리(`ontology-impact.ts`). 런타임 필터가 `stale: { $ne: true }`라
  **사유 객체를 담으면 격리가 통과되던 불일치**를 함께 고쳤다(`stale: null` 기준으로 통일, 4곳).
  대형 별표는 `rowHash` 행 앵커로 완충 — 없으면 한 행 개정에 605건(조문근거의 66%)이 한꺼번에 격리된다.
  행 판정은 정확 일치로 한다(부분 포함으로 완화하면 행 끝 덧붙임을 놓치는 것을 실측 확인).
  전량 판정 시 격리된 16건은 전부 원본 파싱 아티팩트(표 헤더·구분선 혼입, 앞 잘림)였다 — 실제 개정 0건.
  `assets:realign`으로 판정 앵커(`rowText`)를 원문 행에 맞춰 격리 0건이 됐고, 정렬 후에도 같은 행을
  개정하면 그대로 감지된다(감지력 손실 없음). 재실행 시 605건 전부 정합으로 멱등.
- 2026-08-03 P1: 상태 집계 도입. 그 과정에서 **P0 백필이 재적재로 지워지는 결함**을 발견했다 —
  `ArticleSchema`에 `srcHash`가 없어 Mongoose strict가 저장 시 잘라냈고, 적재 라우트·CLI도 해시를 넣지 않았다.
  저장 경로마다 챙기면 반드시 빠지므로 **모델 pre-save 훅**에서 한 곳으로 산정하도록 고쳤다.
  같은 이유로 `regulations-graph-build.ts`의 자체 해시 함수도 `article-hash.ts`로 통일.
  해시 보정 2,468조문 후 212문서 전부 상태 기록, 조치 필요 0건.
