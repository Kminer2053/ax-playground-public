# 사규 원본 폴더 (형식 예시 + 적재 소스)

이 폴더는 지식검색(사규 RAG)이 읽어 들이는 **사규 원본 md/txt의 보관 위치**입니다.
동봉된 9건은 **가상의 예시 사규**로, 각 기관이 자기 사규를 넣기 전에 *형식을 확인하고 기능을 시연*하는 용도입니다.
실제 기관의 사규가 아니며, 그대로 운영에 사용하지 마십시오. 6개 분류가 모두 1건 이상 들어 있어
분류별 청킹 전략을 한 번에 확인할 수 있습니다.

| 파일 | 분류 | 조문 | 검증하는 청킹 전략 |
| --- | --- | --- | --- |
| `규정/규정 제1호_취업규칙(샘플).md` | 규정 | 20 | 조문(JO) 청킹 + 장(章) 구분자 |
| `규정/규정 제2호_문서관리규정(샘플).md` | 규정 | 15 | 표준 조문형(JO) |
| `규정/규정 제3호_위임전결규정(샘플).md` | 규정 | 13 | **별표(markdown 표)** 분리 — 전결표의 기준표(A등급) 분류·행 명제화 |
| `규정/규정 제4호_인사규정(샘플).md` | 규정 | 18 | 별표(징계양정 기준표) + 타 사규(「취업규칙」)·법령(「근로기준법」) 인용 → ref·law 엣지 |

## 1. 폴더 구조 = 분류(category)

```
data/regulations-2026/
  규정/      ← 이 첫 번째 폴더 이름이 그대로 문서 분류가 된다
  세칙/
  지침/
  매뉴얼/
  편람/
  계약서/
```

파일을 폴더 없이 최상위에 두면 분류를 인식하지 못합니다. **반드시 분류 폴더 아래**에 두십시오.
분류에 따라 청킹 전략이 달라집니다(규정·세칙·지침 = 조문형, 계약서·매뉴얼 = 전용 청킹).

## 2. 파일 형식

### 프런트매터(맨 앞 `---` 블록)

```
---
규정명: 취업규칙(샘플)
규정종류: 규정
최종시행일: 2026.01.01
원본파일: 규정 제1호(취업규칙-샘플)-2026.01.01.md
비고: 원문 HWP 재추출
---
```

| 키 | 필수 | 설명 |
| --- | --- | --- |
| `규정명`(또는 `문서명`) | 권장 | 문서 제목. 없으면 파일명에서 유추한다 |
| `규정종류`(또는 `문서종류`) | 선택 | 없으면 폴더명(분류)을 사용 |
| `최종시행일` | 권장 | `YYYY.MM.DD`. 없으면 본문의 최신 부칙 시행일 → 파일명 날짜 순으로 유추 |
| `원본파일` | 선택 | 추적용 원본 파일명 |
| `비고` | 선택 | 자유 메모 |
| `청킹` / `청킹깊이` / `청크상한` | 선택 | 조문 체계가 아닌 문서(편람 등)의 청킹 노브. 일반 규정은 쓰지 않는다 |

파일명에 `제N호`가 들어 있으면 문서 연번으로 인식합니다(예: `규정 제1호_취업규칙(샘플).md` → `제1호`).

### 본문

- **조문 머리는 줄 맨 앞에서 시작**해야 합니다: `제1조(목적)` → 다음 줄부터 본문.
- 장·절 머리(`제1장 총칙`)는 조문들의 상위 그룹 구분자가 됩니다.
- 항은 `①②③`, 호는 `1. 2. 3.`, 목은 `가. 나. 다.`로 적습니다.
- 개정 이력 표시는 `<개정 2026.01.01>` 형식으로 조문 끝에 붙입니다.
- **제1조 앞에는 본문을 두지 마십시오**(표지·연혁으로 간주되어 청크에서 빠집니다).
- 부칙은 본문 마지막에 `부칙 <제2026-01호, 2026.01.01>`처럼 적으면 1개 청크로 묶입니다.
- 별표·별지·서식은 **부칙 뒤**에 `[별표 1] 제목 (제5조 관련)` 머리줄 + markdown 파이프 표로 적습니다.
  각 별표가 1개 청크가 되고, 기준표(전결표·양정표 등)는 자동으로 A등급으로 분류되어 행 단위 명제화 대상이 됩니다.

## 3. 적재 방법

### (a) 관리자 화면 — 권장

관리자(`/admin`) → **사규** 탭 → 파일 업로드. HWP/HWPX/PDF/DOCX 원본을 그대로 올리면
추출 → 청킹 → 자가검수(good/warn/bad) → 변경점 diff 확인 후 커밋하는 절차가 화면에서 진행됩니다.
md/txt는 이미 정제된 것으로 보고 추가 정규화 없이 적재합니다.

### (b) CLI — 파일 1건 재적재

```bash
# 미리보기(DB 미변경): 청킹 결과·검수 점수·변경점만 출력
npm run reg:ingest -- --file "data/regulations-2026/규정/규정 제1호_취업규칙(샘플).md" --category 규정 --dry

# 실제 적재
npm run reg:ingest -- --file "data/regulations-2026/규정/규정 제1호_취업규칙(샘플).md" --category 규정
```

### (c) CLI — 이 폴더 전체 재구축

```bash
npx tsx src/scripts/import-regulations.ts                 # dry-run: 전 파일 파싱 리포트
npx tsx src/scripts/import-regulations.ts --commit        # rag_regulation 전체 재구축(백업 필요)
npx tsx src/scripts/import-regulations.ts --sagyu         # public/sagyu.json(클라이언트 키워드검색) 재생성
```

`--commit`은 `npm run backup:regulations`로 만든 백업이 `backups/`에 있어야 실행됩니다.

## 4. 자가검수 기준

적재 시 문서마다 보존율·빈 조문·중복 청크명·부칙 누수 등을 점검해 `good` / `warn` / `bad`를 매깁니다.
`bad`는 적재가 중단되므로, 원본의 조문 머리 형식(줄 맨 앞 `제N조(제목)`)을 먼저 확인하십시오.
동봉된 예시 9건은 모두 `good` 또는 `warn` 없이 적재됩니다.

## 5. 정제 보정 맵 (txt 원본을 쓸 때만)

`src/scripts/regulations-cleanup-map.json`은 **txt 원본**에서 글자가 한 칸씩 벌어져 추출된 줄
(예: `제 1 조 ( 목 적 )`)을 사람이 확인한 정답 줄로 바꾸는 1:1 보정표입니다.

- 키(원문)와 값(교정문)의 **공백을 뺀 글자열이 완전히 같아야** 적용됩니다(다르면 무시하고 자동 정제로 폴백).
- md 원본에는 적용되지 않습니다. 동봉된 예시 9건은 md라서 필요 없으면 `{}`로 비워도 됩니다.

## 6. 주의

- 이 폴더의 내용은 그대로 검색 결과·답변 근거로 노출됩니다. **개인정보·연락처·미공개 자료를 넣지 마십시오.**
- 예시 파일은 언제든 삭제해도 됩니다. 폴더가 비어 있으면 `--sagyu`는 기존 `public/sagyu.json`을 유지합니다.
