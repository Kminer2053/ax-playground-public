# 사규 데이터 MongoDB 시드 — 실행 가이드

기관 사규를 MongoDB에 넣고 사규 텍스트 검색(MongoDB `$text` 전문검색 + 키워드 매칭)을 쓰는 절차입니다.

> **사규 데이터 출처(현행)**: `data/regulations-2026/` 폴더. 분류 폴더 6종(규정·세칙·지침·매뉴얼·편람·계약서)으로 구성되며, 원본은 HWP·PDF + 정제 `.md`/`.txt`입니다. `src/scripts/import-regulations.ts`가 이 폴더를 자동 탐색해 **조문(청크) 단위로 파싱·저장**합니다. (하드코딩 목업이 아니라 파일 파싱)
>
> ※ **레거시(ax-portal 시절)**: 구 `data/regulations`(또는 `ax-portal/data/regulations`)의 TXT **74건** + `npm run seed:regulations`는 **현행이 아닙니다.** 현행 적재 경로는 아래 `import-regulations`입니다.
>
> ※ 레거시 모바일 HTML(`public/panels/mobile/`)은 미사용 코드로 공개판에서 삭제되었습니다. 정식 데이터 소스는 위 `data/regulations-2026`입니다.

---

## 1. 사전 준비

- **MongoDB** 준비, `MONGODB_URI` 설정 완료. DB명은 `MONGODB_DB`(미설정 시 `axplayground`)를 따릅니다.
- (선택) Ollama / `OLLAMA_EMBEDDING_MODEL`: 현재 검색은 임베딩을 사용하지 않으므로 **불필요**합니다. 향후 벡터 검색 도입에 대비한 예약 설정입니다.

---

## 2. 검색 방식 (Atlas Vector Search 불필요)

사규 검색은 MongoDB Atlas **Vector Search 인덱스를 쓰지 않습니다.**
**MongoDB `$text` 전문검색 + 정규식 키워드 매칭** 하이브리드로 관련 조문을 회수합니다. (임베딩/코사인 유사도는 현재 미사용)
※ 적재된 문서의 `embedding` 필드는 항상 `null`이며, 향후 벡터 검색 도입을 위한 자리만 마련해 둔 상태입니다.

---

## 3. 적재 실행 (현행: import-regulations)

프로젝트 루트에서 `src/scripts/import-regulations.ts`를 직접 실행합니다.

```bash
# (1) 드라이런 — DB 미변경. 파싱·청킹 리포트 출력 + /tmp/reg-dryrun.json 저장
npx tsx src/scripts/import-regulations.ts --dry-run
#   옵션: --limit N / --cat 매뉴얼 / --file <부분문자열> 로 범위 제한 가능

# (2) 실제 적재 — rag_regulation 컬렉션 비우고(드롭) 재삽입. 백업 선행 필수
npm run backup:regulations               # 먼저 백업 (backups/regulations-* 생성)
npx tsx src/scripts/import-regulations.ts --commit

# (3) 좌측 키워드검색 색인 재생성 — public/sagyu.json 파일 기반 재생성
npx tsx src/scripts/import-regulations.ts --sagyu
```

- **동작**: `data/regulations-2026/`를 자동 탐색해 분류별로 파싱하고, 조문(청크) 단위로 DB(`rag_regulation` 컬렉션)에 저장합니다. **임베딩은 생성하지 않으며 `embedding` 필드는 `null`로 저장**됩니다.
- **`--dry-run`**: DB를 건드리지 않고 파싱·청킹 결과만 리포트하며, 전체 문서를 `/tmp/reg-dryrun.json`으로 떨어뜨립니다.
- **`--commit`**: 먼저 `backups/regulations-*` 백업이 있어야 진행됩니다(없으면 `npm run backup:regulations`부터). 이후 `rag_regulation`을 비우고 신규 데이터로 재삽입합니다. 완료 시 `재구축 완료: 규정 N건 / 청크 M개` 로그를 출력합니다.
- **`--sagyu`**: 좌측 클라이언트 키워드검색용 `public/sagyu.json`을 파일 기반으로 재생성합니다(category 포함).
- **빌드 시 자동 실행**: `npm run build`는 `import-regulations --sagyu` 후 `next build`를 수행합니다(빌드 시 `public/sagyu.json` 갱신).

### 3-1. 관리자 화면 적재 (대안)

`/admin`의 **사규 적재 탭**에서도 적재할 수 있습니다. 파일 업로드 → 파싱 미리보기 → 교체/신규 적재 흐름이며, 자가검수 게이트를 통과해야 반영됩니다. 스캔 PDF는 OCR(RapidOCR + pymupdf 페이지 래스터화)로 텍스트를 추출합니다.

### 3-2. 폐쇄망 시드 (스냅샷 복원, 대안)

폐쇄망에서는 위 적재 대신 MongoDB 스냅샷 복원으로 채울 수 있습니다.

```bash
mongorestore data/mongo-snapshot/dump-2026-08-08
```

스냅샷에 담긴 사규·외부 법령이 함께 복원됩니다(`rag_regulation`).

## 4. 확인

- 법무 패널 "사규 검색" 사용 시, MongoDB에 저장된 사규 기준으로 텍스트 검색(`$text` + 키워드)이 이뤄집니다.
- `npm run db:status`로 `rag_regulation` 컬렉션 문서 수를 확인할 수 있습니다.
- **동봉 샘플 기준**: 9건(규정 4 · 세칙 1 · 지침 1 · 매뉴얼 1 · 편람 1 · 계약서 1) — 기관 사규로 교체해 적재하면 건수가 그만큼 늘어납니다.

**정리**: `npx tsx src/scripts/import-regulations.ts --commit` 실행(백업 선행) → `data/regulations-2026`의 사규가 MongoDB(`rag_regulation`)에 조문 단위로 저장되고 텍스트 검색이 동작합니다. (별도 벡터 인덱스 단계는 없으며, `embedding`은 `null`로 저장됩니다. 구 `seed:regulations`로 TXT 74건을 넣던 방식은 레거시입니다.)

## 5. 개정본 1건 재적재 (권장 경로)

규정이 개정되면 전체 재적재 대신 **그 문서 1건만** 교체합니다 — 관리자 UI(사규 적재 탭: 변경 4분류(실질/명칭/마커/표기차)·조문 인라인 diff 검수) 또는 CLI:

```bash
MONGODB_URI="mongodb://127.0.0.1:27017/axplayground" \
npm run reg:ingest -- --file "/경로/계약업무 처리지침.hwp" --category 지침   # --dry: 미리보기만
```

- 시행일(최신 부칙 자동추출)·연번(공란 시 기존 승계)·위계 부모 자동. 스캔 PDF는 OCR 자동 승격.
- 임베딩·지식그래프 **증분 갱신**: 무변경 조문은 `srcHash`로 기존 벡터·엣지 재사용(재계산 = 변경 조문만). 상세: [`RAG_GRAPHRAG.md`](RAG_GRAPHRAG.md) §8.
- 시드에 반영하려면 스냅샷 재생성: [`../data/mongo-snapshot/README.md`](../data/mongo-snapshot/README.md) "새 스냅샷 만들기".
